Authoring guide

Create Your First Page

Start with a working shell, write for your audience, and select adopted patterns for the content you need to explain.

1. Copy a Working Starter

Use these commands to obtain a fresh checkout and create a consumer page. If you already have a checkout, start at its root and skip the first two commands. This creates a separate consumer site in a new directory named my-docs; choose a different name if it already exists.

git clone https://github.com/martinbechard/docs-design-system.git
cd docs-design-system
mkdir ../my-docs && mkdir ../my-docs/assets && \
cp docs/design-system/assets/design-system.css ../my-docs/assets/ && \
cp docs/design-system/VERSION ../my-docs/assets/VERSION && \
cp docs/design-system/templates/page.html ../my-docs/index.html && \
python3 -c 'from pathlib import Path; p=Path("../my-docs/index.html"); p.write_text(p.read_text().replace("../assets/", "assets/"))'
git rev-parse HEAD

Record the printed commit beside your copied assets so the adopted source can be recovered. Open the starter preview and completed example to compare their structure. Copy the CSS and version file from the same checkout as the template; do not link production pages to a moving “latest” stylesheet.

my-docs/
├── index.html
└── assets/
    ├── design-system.css
    └── VERSION

2. Write and Compose

  1. Replace the title, product name, introduction, headings, and starter text with source-backed content for your audience.
  2. Use .ds-header, .ds-footer, and .page-nav from the starter. Keep the skip link, unique main landmark, and exact version metadata.
  3. Choose content patterns, tables and metrics, or diagrams when they help explain the subject. Do not populate a page with every component.
  4. For a multi-page suite, use identical destination labels and order on every page and mark only the current page with aria-current="page". Add previous/next links only when a reading sequence exists.
  5. Use your own branding and truthful provenance. A text product identity works without a logo. Retain applicable copyright notices in copied source.

Static pages need no JavaScript

The catalog’s design-system.js demonstrates forms and settings. It is not a general application runtime. Native details works without it. When adding custom interactions, implement and verify the required behavior, including keyboard operation, focus movement, validation, and recovery.

3. Preview Locally

From the repository root, serve the copied site:

python3 -m http.server 8000 --bind 127.0.0.1 --directory ../my-docs

Open http://localhost:8000/. Stop the server with Ctrl+C. To preview this catalog instead, use --directory docs/design-system.

4. Review and Publish

Review the rendered page and its source in consumer mode. Check desktop and narrow widths, keyboard navigation, local links and fragments, content accuracy, and every interaction present. A source-only check cannot prove visual or keyboard behavior.

Publish your consumer directory using your project’s static hosting workflow. In this repository, pushes to main automatically publish docs/design-system/ through GitHub Pages. Files outside that folder are not included.

Use with an Agent

The repository contains two local skills. They are not automatically installed into your runtime. In a checkout, ask your agent to read the relevant file:

Use skills/create-documentation-page/SKILL.md to create a page
about our deployment process from the supplied project sources.
Write it to my project’s docs folder and review it in consumer mode.

Use skills/review-documentation-design-system/SKILL.md to review
my page in consumer mode against its pinned design-system version.

Keep the complete repository available when using these skills: they reference the catalog, starter, and each other by relative path. Review mode catalog is for maintaining this reference site; it includes specimen and historical evidence checks that do not apply to consumer documents.

Adopt a Version Deliberately

The current version is 0.2.0, a usable draft before 1.0.0. Keep the exact version in the page metadata, visible footer, and copied assets/VERSION. An existing consumer remains pinned when this repository changes.

To upgrade, inspect the changelog, replace assets from one selected checkout, apply required markup changes, and review the page before updating its declared version. Historical audit commits describe provenance; they are not asset versions.
